# Resonance: three-minute Vlogbrothers demo

Use one story throughout: **a creator takes an existing book-publishing video through review, an editorial decision, an exported edit plan and re-reviewed revision, and a complete content package.** Present this as a Vlogbrothers-themed demonstration using attributed public material, not as an endorsement or an actual customer relationship.

Three minutes can show every major workflow, but cannot explain every control. Give the review loop about a minute; show the remaining capabilities through short, prepared results. The detailed feature checklist below is the recording/preparation guide.

## 1. Prepare before recording

1. Sign in at <https://habeas-codus.web.app> with your **editable account**. The shared “Try demo” account is read-only; it cannot create projects, accept findings, upload revisions or generate assets. At inspection, its dashboard still contained unrelated sample projects.

4. Create the hero project and upload the local MP4. Let transcription and the first review finish **before** you rehearse the sequence. Do not put the known correction into the initial brief, persona or transcript.
5. Check the actual findings. The target claim occurs at **00:25.440–00:36.640**. Use the finding returned by the app; its exact title, severity, span and reviewer count can vary. Do not fabricate a finding if this live run misses it.
6. Export the edit plan (.edl/.md) for one useful accepted finding, apply it in a real editor, upload the result as a new revision and re-review it. Prepare the original and completed comparison for the recording. Only describe a finding as resolved if the comparison actually shows it.
7. Generate one written draft and one script, one caption render, one Hindi dub, two thumbnail concepts, one listing and one local visual insert. Save/download the results so the recording is not dependent on job completion.
8. Prepare Publish and Calendar **without submitting the Vlogbrothers source to a connected platform**. The existing hero instructions explicitly prohibit publishing that source as demo preparation. Show the filled forms. Use your own original recording in a separate project if you want to demonstrate an actual upload or scheduled post.
9. Record at 1920×1080 if available, hide bookmarks and private account details, close unrelated tabs, and silence desktop notifications. Keep UI text readable. Record individual scenes and add the voiceover afterward.
10. Cut out model/render waits and use a brief “Processing time shortened” overlay where you join a request to its completed result. This is a three-minute edited demonstration, not a claim that all jobs finish in three minutes.

## 8. Edit plan, revision and re-review

Stay on **Review** after accepting/revising a suitable finding. The app no longer renders cuts itself.

1. In **Export edit plan**, choose **Cut** for a genuine removal and **Note** for an instruction that needs manual editing or rerecording. Changing text alone cannot make the original audio say a corrected fact.
2. Inspect the proposed removals and the duration before → after. Cuts snap to speech pauses, and unsuitable very short/long cuts are skipped with a reason.
3. Download **cut list (.edl)** at the source frame rate and **edit plan (.md)**. Apply them in a real editor (Resolve/Premiere import the EDL) and export the edited video. Report the actual saved time, not a target chosen in advance.
4. Click **Upload revision** with the edited file, wait for transcription, then **Run review again**. Complete this before recording.
5. Show the **Before / After** comparison, which opens automatically for the previous revision's review → the new one, with the actual resolved/persisting/new findings. Heavily re-recorded passages can show as unaligned; only call a finding resolved if the comparison shows it.
6. Activating a source revision or editing the transcript can make prepared metadata stale; regenerate affected assets after the final active version is chosen.
