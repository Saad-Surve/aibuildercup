# 2026-10-11 23:49 — Missed 23:42 upload: fired it live + fixed the silent calendar fallback

## What happened (user report, 23:45)

A video meant to go live at 23:42 never uploaded. Investigation (live Firestore):

- Slot `67982d89…` (project "Something", ankit) sat at **status `planned`,
  `publishId: None`** — a plan-only calendar entry, so nothing ever fired.
- Both preconditions for a real upload *did* exist: YouTube connection
  `a818ae4d…` `connected` (re-authed 23:23:39) and the project had a ready
  source video. Slot was created 23:24:05 — 26 s after the reconnect.

## Root cause

`web/src/components/calendar/schedule-dialog.tsx` (`createUpload` path) gated the
real publish on a connected channel + source video, but read the **cached**
connections list:

```ts
connectionsQuery.data?.items ?? (await connectionsQuery.refetch())…
```

If cached data existed at all (here: from before the 23:23 reconnect), the
refetch never ran → no channel found → **silent fallback** to a plan-only slot
with a misleading "connect a channel" toast. Same class of race existed for
`projects` (no refetch fallback at all; an in-flight list reads as "no source
video").

## Fix 1 — the missed upload went live

Replayed exactly what the dialog should have done (one-off script, since
removed): `PublishService.create` with source video, title "Something",
`publishAt` = the missed 18:12 UTC moment (past → worker uploads **public
now**, per the worker's go-live logic), linked the **existing** slot to the new
publish, ran `run_publish` inline.

- Publish `e24d515a…`: **published**, job `5fd54559…` succeeded.
- Live: https://www.youtube.com/watch?v=Yy--rrT5KsY
- Slot flipped to `published` via `mark_linked_published` (no manual edit).

## Fix 2 — the silent fallback (web)

`schedule-dialog.tsx`: both `connectionsQuery` and `projectsQuery` are now
**always refetched at save time** inside the mutation; cached data is never
trusted for the upload gate. `oxlint` + `tsc` clean.

## Gotchas / notes

- `refetch()` works on disabled queries, so the project-side dialog
  (`fixedProjectId`, query disabled) is covered too.
- The "planned slot fires nothing" model is by design (uploads ride on
  `publish.publishAt`; YouTube holds the video until then). A sweeper that
  auto-converts due planned slots is possible future scope, not done.
- Three earlier test publishes today (17:21 UTC slot) show `deleted` —
  user deleted them on YouTube directly; reconcile works as intended.
