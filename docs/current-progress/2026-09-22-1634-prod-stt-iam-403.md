# Progress — 2026-09-22 16:34 UTC — prod STT 403 fixed (API SA missing Speech role)

A real upload failed in production. Cloud Run logs showed the STT call erroring:

```
google.api_core.exceptions.PermissionDenied: 403 Permission 'speech.recognizers.recognize'
denied on resource '//speech.googleapis.com/projects/538724167565/locations/us/recognizers/_'
```

## Cause

Transcription runs **inline in the API Cloud Run service** (`transcribe_after_response`
background task) as `creator-studio-api@habeas-codus.iam.gserviceaccount.com`. But
`infra/iam.tf` only granted `roles/speech.client` to the separate **`transcribe`** service
account (`sa_roles.transcribe`). The API SA never had Speech access — the previous session's
"verified live" runs used the engineer's ADC, not the runtime SA, so this was never exercised.

## Fix

- Added `roles/speech.client` to `sa_roles.api` in `infra/iam.tf`.
- Granted it live: `gcloud projects add-iam-policy-binding habeas-codus
  --member=serviceAccount:creator-studio-api@... --role=roles/speech.client`.
- `terraform apply` reconciled the member into state (`api--roles/speech.client` now tracked).
