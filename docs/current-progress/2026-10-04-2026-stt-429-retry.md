# Fix: Speech-to-Text 429 (retry with backoff)

## What the user hit

Uploading a video failed transcription with
`google.api_core.exceptions.ResourceExhausted: 429 Resource has been exhausted (e.g. check quota).`

## Cause

Speech-to-Text is rate-limited **per region**: 150 batch-recognition requests and 150 Operation
requests per 60 seconds (per the STT quotas page). A burst — several uploads, or a job that was
retried — trips the limit and the long-running operation call raises `ResourceExhausted`. The
traceback shows it failing at `operation.result()` (the polling RPC), not at request creation.

## Fix

`providers/stt.py`: `_recognize_with_retry` wraps `batch_recognize` + `operation.result` and retries
`ResourceExhausted` with exponential backoff (default 4 attempts, base 3s → 3/6/12s). Re-creating
the operation is safe — the transcribe job is idempotent. Config: `STT_MAX_ATTEMPTS`,
`STT_RETRY_BASE_SECONDS`. The diarization fallback is unchanged.

## Verification

- `uv run ruff check .` clean; `uv run mypy app` clean (114 files).

## Gotchas

- The error is transient (per-minute rate limit), not a hard cap: a single retry after a minute
  would also have worked. The backoff makes it self-heal.
- If a burst is large, the STT provider retries the whole call; each retry may create a new
  operation. Fine at demo scale; a production version could retry only the polling RPC.
