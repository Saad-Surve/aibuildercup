Flow implemented: initialize Firebase Auth → subscribe to auth state → `onAuthStateChanged`
gives the user → `apiFetch("/me")` (the existing client attaches `Bearer <ID token>`) → backend
verifies with Firebase Admin and lazily creates `users/{uid}` → the page renders the returned
profile (uid, email, onboarding, persona version, preferences) with a "Authenticated" badge.

## 2. Decisions

- **Google sign-in only for now.** Identity Toolkit shows `defaultSupportedIdpConfigs/google.com`
  `enabled=true`; the `signIn` config has no `email` block, so email/password is not enabled.
  `EmailSignInForm` from the plan is deferred until that provider is turned on.
- **No onboarding/dashboard pages yet**, as requested. After sign-in the login page itself shows
  the backend profile, which is enough to verify the whole chain. Redirects to `/onboarding` and
  `/dashboard` come when those routes exist.
- **Root redirect** `/` → `/login` so verification is one click. The default Next starter page is
  gone.
- The page is a Client Component (auth + browser APIs); the route file stays a thin server
  component that renders `<LoginPage />`.
- Icons are inline SVG rather than `lucide-react`, to avoid any icon-name surprises on the
  unusual `lucide-react@1.47.0`.

## 4. How to verify (user)

1. Open `http://localhost:3000/login`.
2. Click **Continue with Google** and pick an account.
3. Expect the profile card with "Authenticated — `GET /me` returned this profile from the backend."
4. Check the backend log: `GET /me 200`, and a `users/{uid}` document is created in Firestore.
