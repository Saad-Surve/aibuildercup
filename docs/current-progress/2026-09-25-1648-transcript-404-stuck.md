## Root cause

Two defects, both in the web query layer. No backend or data involved.

**1. The transcript query was the only polling query in the workspace without
`refetchIntervalInBackground`.**

TanStack Query `queryObserver.js`:

```js
this.#refetchIntervalId = timeoutManager.setInterval(() => {
  if (this.options.refetchIntervalInBackground || focusManager.isFocused()) this.#executeFetch();
}, this.#currentRefetchInterval);
```

`focusManager.isFocused()` is `document.visibilityState !== "hidden"` (it listens
for `visibilitychange`, not `focus`). So when the tab is hidden, the interval keeps
ticking but **the fetch is skipped outright**.

`project-workspace.tsx` (project + job) and `review-panel.tsx` (run, reviewers,
heatmap, findings) all set `refetchIntervalInBackground: true`.
`transcript-panel.tsx` did not. Transcription outlasts a tab switch, so this is
exactly the case that mattered, and the differential in the logs matches the
differential in the code — the one query that paused was the one missing the flag.

**2. (Introduced by me in `067232e`.) Two observers on `["transcript", projectId]`
with different options.**

`TranscriptPanel` declared the query with `refetchInterval`, `refetchOnMount:
"always"`. My new `ReviewPanel` declared the *same key* with `retry: false` and
neither. Two observers, one shared query, divergent policies. Query-level recovery
in TanStack is `this.observers.find((x) => x.shouldFetchOnWindowFocus())?.refetch()`
— **`.find()`, not `.some()`** — so a query's recovery behaviour depends on
whichever observer happens to come first. Options on a shared key can silently
suppress each other.

## Fix

New `web/src/hooks/use-project-transcript.ts` — a single shared hook holding every
load-bearing rule, consumed by both panels:

- `refetchIntervalInBackground: true` — the actual bug
- `staleTime: 0` — until there is data there is nothing to be fresh; the app-wide
  default is 30s
- `refetchInterval: data ? false : 3000` — never stop polling while absent
- `refetchOnMount: "always"` and `refetchOnWindowFocus: true`

`transcript-panel.tsx` and `review-panel.tsx` both call `useProjectTranscript()`.
There is now exactly **one** declaration of that query's options, so the two
observers cannot disagree. The `invalidateQueries(["transcript", …])` calls in
`project-workspace.tsx` (on job success and on project `ready`) stay as a fast
path.

Note: `isStaleByTime` returns `true` whenever `data === undefined`, so `staleTime`
was not itself blocking recovery for this query. Setting it to 0 is defensive — it
stops the same class of mistake if someone later adds `initialData` or a
placeholder.

## Known small issue (not addressed)

While a project has no transcript at all (e.g. transcription failed), the hook
keeps polling every 3s for as long as the tab is open. That is pre-existing
behaviour and now also continues in a background tab. Cheap, but a failed project
should stop the poll once the job is known-failed — needs a `enabled` gate wired
from the project/job status.
