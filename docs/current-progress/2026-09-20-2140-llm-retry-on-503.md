# Progress — 2026-09-20 21:40 IST

Status: **Persona fell back to the template because Gemini returned a transient 503. The LLM
provider now retries 429/5xx with backoff before giving up.**

## 1. What was reported

Onboarding on the deployed site produced the deterministic template persona, not a generated one.

## 2. Root cause (from Cloud Run logs)

```
2026-09-20T15:57:20Z ERROR Traceback ... persona_service.py line 225 in _generate_markdown
  ... llm.py line 80 in _real
google.genai.errors.ServerError: 503 UNAVAILABLE. This model is currently experiencing high demand.
→ "Persona generation failed; using deterministic template"
```

The key, the Secret Manager mount, and the new AI-Studio code all worked — the call reached Gemini.
`gemini-flash-latest` was just overloaded at that moment. `PersonaService` catches every exception
and returns `build_persona_markdown`, so a transient 503 silently degraded to the template.

## 3. Fix

- `app/providers/llm.py`: `_real` retries `429, 500, 502, 503, 504` up to `llm_max_attempts` with
  exponential backoff (`llm_retry_base_seconds * 2**(attempt-1)`), logging each retry. Non-transient
  errors (4xx like 404) still fail fast.
- `app/config.py`: `llm_max_attempts = 4`, `llm_retry_base_seconds = 0.5` (worst case ~3.5s of
  sleeps before falling back).
- `.env.example`: documented both knobs.
- `tests/test_providers.py`: a flaky-client test asserts a 503 is retried and then succeeds, and a
  404 is not retried.

The template fallback stays: onboarding must never hard-fail because an upstream model is busy.

## 4. Verification

`uv run pytest` → **95 passed** (was 93). `ruff` and `mypy` clean.

## 5. How to get a real persona after deploy

The onboarding answers are already saved, so either:
- go to Profile → Edit persona, step through to **Platforms**, and click **Generate persona**
  (this re-calls `POST /onboarding/complete`), or
- redo onboarding from a fresh user document.

A successful generation writes a new cassette under `fixtures/cassettes/llm/`.
